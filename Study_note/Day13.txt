一、交付物

KnowledgeBaseEntity 映射 core.knowledge_bases，领域 record 保持独立。
fromNew() 用于 ACTIVE 新建对象，toDomain() 保留原 ID、状态和时间。
name_key 由 PostgreSQL 生成，JPA 不主动写入。
JpaKnowledgeBaseRepository 用原生 EXISTS 查询非 DELETED 范围，大小写规则与生成列一致。
PostgresKnowledgeBaseRepository 实现领域 Repository，成为实际 Spring 数据访问实现。
内存 Repository 保留给手动构造的单元测试，移除 @Repository。

二、事务和异常的当前实现记录

adapter 类的查询事务 readOnly=true；save() 单独声明写事务。
saveAndFlush() 在 try 内将变更发送到数据库，flush 不等于提交。
只将 SQLState=23505 且约束名=uq_live_kb_name 转为 KnowledgeBaseNameConflictException。
外键等其他完整性错误仍抛出 DataIntegrityViolationException，不误报重名。
Service 预查重改善普通失败路径；数据库索引负责最终唯一性。

五、实际范围和后续事项

数据现在存于 PostgreSQL；Spring 重启不再清空知识库。
查询仍是读出全部记录后在 Java 过滤、排序和分页，没有数据库分页。
新建映射还不能用于生命周期更新或删除，避免覆盖删除元数据。
Java Instant 可带纳秒，PostgreSQL 精度为微秒；重启验收比较两次 GET 的读库值。
顺序 HTTP 重名与 adapter 约束转换测试不等于完成并发压力测试。
固定演示身份、认证授权、JSON 协议差异、requestId 与响应缓存规则等见 Day 14 验收记录。
历史 Day 10/11 脚本有固定名称/空表前提，重启不能恢复这些前提；当前使用 Day 13/14 文件。
