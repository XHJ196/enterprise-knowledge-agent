一、HTTP 状态与业务错误码

HTTP 状态表达请求结果类别，code 表达具体业务原因。
201 / SUCCESS：知识库创建成功。
409 / KNOWLEDGE_BASE_NAME_CONFLICT：知识库名称冲突。
422 / VALIDATION_ERROR：名称或简介不符合规则。
500 / INTERNAL_ERROR：服务端未预期错误。

统一 JSON 结构为 {code, message, data, requestId}。
错误 data 为 null；message 是说明文字，调用方应按状态和 code 判断行为。
创建成功的 Location 指向 /api/v1/knowledge-bases/{id}。

二、异常应该在哪一层处理

Domain 检查核心业务规则，声明出了什么问题，不决定 HTTP 状态。
Application 编排创建用例、查询重名并保存。
Controller 接收 HTTP 请求，调用用例并构造成功响应。
@RestControllerAdvice 将已知异常统一转换为 HTTP 错误响应。
这样每个 Controller 可以专注于接口职责，错误契约由一处维护。

KnowledgeBaseValidationException extends IllegalArgumentException。
它用于名称和简介的输入规则；普通 IllegalArgumentException 仍可能来自内部错误。
createdBy 由服务端提供，其缺失不能归咎于客户端填写错误。
Spring 优先选择更具体的 @ExceptionHandler，匹配不取决于方法书写顺序。
未预期异常只返回固定通用消息，不返回 exception.getMessage() 中的内部细节。

三、requestId 和过滤器

RequestIdFilter 为请求设置属性，并给响应设置 X-Request-Id。
Controller 和异常处理器读取请求属性，将相同 ID 放进 JSON。
filterChain.doFilter(request, response) 将请求传递给后续处理链。
遗漏此调用时，Controller 不会执行，可能看到默认 200 和空响应，不能据此判断业务成功。
当前实现会沿用非空客户端请求头，否则生成 UUID；来源与格式限制仍列为技术债。
requestId 用于追踪请求，不是用户身份，也不提供业务幂等性。

四、代码风格

ResponseEntity.status(int) 和 status(HttpStatusCode) 都可设置 HTTP 状态。
项目统一使用 HttpStatus 枚举：CONFLICT、UNPROCESSABLE_CONTENT、INTERNAL_SERVER_ERROR。
当前依赖为 Spring Boot 4.1.2、Spring Framework 7.0.10；UNPROCESSABLE_CONTENT 对应 422。
