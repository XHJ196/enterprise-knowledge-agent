# 企业知识库 Agent 平台 PRD

**版本：** v1.0  
**评审日期：** 2026-11-18  
**评审状态：** 需求评审通过，可进入技术设计与第一版实施。  
**适用范围：** 个人作品集的本地演示版本。

## 1. 产品背景及目标

**项目定位：** 本项目用于个人作品集，模拟企业内部文档管理与知识问答场景。第一版通过预置的管理员和普通员工账号，演示文档维护、权限控制、资料查询、文件下载及带来源引用的知识问答流程。

**产品名称：** 企业知识库 Agent 平台

搭建一个智能企业文档管理系统，方便公司人员快速查询内部文档并解决相关疑惑

**演示数据与接入方式：** 本项目使用自拟的企业样例资料或公开且允许使用的技术资料进行演示。自拟资料标注为演示内容，公开资料保留来源。第一版由管理员通过文件上传导入资料，用于验证文档处理、知识库授权、资料查询、文件下载、知识问答和来源引用等功能。

## 2. 用户角色与责任矩阵

### 2.1 用户角色

- 企业管理员：管理用户、知识库和访问权限，负责文档的上传、更新和删除；文档处理成功后由系统自动发布。
- 普通员工：查找、查看和下载自己有权访问的文档，进行知识问答并查看来源引用；不具备文档上传和维护权限。

### 2.2 责任矩阵

- 文档的上传、更新和删除——企业管理员。
- 文档的查找、查看、下载，以及知识问答和来源查阅——普通员工，仅限其有权访问的资料。
- 员工列表查看，以及知识库访问权限的授予和撤销——企业管理员。

## 3. 用户痛点与核心使用场景

### 3.1 用户痛点

- 企业文档分散，员工难以快速找到资料。
- 新员工需要花大量时间了解内部流程
- 员工经常重复询问相同的业务问题
- 普通的大模型平台并不知道企业内部的私有知识

### 3.2 第一版优先解决的场景

第一版优先演示员工查询企业制度的场景，以出差报销为主要示例。

员工选择已获授权的知识库，询问报销材料、提交期限等问题。系统根据已发布文档回答，提供来源引用，支持核对原文和下载文件。

资料不足时明确说明无法确认；资料存在无法消除的冲突时，展示不同说法及引用，提示联系管理员核实。

演示使用自拟制度，具体规定以样例文档为准。

### 3.3 核心使用场景

1. 员工快速查询企业内部资料——员工登录注册后，进入企业内部，可以访问有权限的相关资料，同时通过Agent来快速找到自己想要的资料。

2. **员工进行知识问答：** 员工选择一个有权访问的知识库后输入问题，无需先找到或选中具体文档。系统在该知识库已发布的文档中查找依据，生成回答并展示来源引用，方便员工核对原文。

3. 企业管理员查看员工列表，选择员工，并为其授予或撤销知识库访问权限。

4. 企业管理员可以上传新文档或替换已有文档，并查看处理状态。替换文件通过上传校验后，旧内容停止提供服务；新内容处理成功后自动发布，处理失败时由管理员重试或重新替换。

5. 资料维护与核实——企业管理员通过替换文件和删除文档维护制度资料。问答发现无法依据文档消除的冲突时，展示不同说法及各自引用，提示员工联系管理员核实。历史回答的来源变更或失效时，按“来源变更后的历史引用”规则提示过期风险。

## 4. 功能需求

### 4.1 注册与登录

支持用户自行注册和使用账号密码登录。自行注册成功的账号统一为普通员工，注册页面不提供管理员角色选项，服务端不允许通过注册接口创建管理员账号。

系统预置管理员和普通员工账号，供作品集演示使用。

登录成功后，根据账号角色和访问权限限制可执行的操作；账号或密码错误时，提示登录失败。

新注册账号默认为普通员工，初始不授予任何知识库访问权限。管理员完成授权后，该员工才能访问对应知识库。预置的演示员工账号提前配置知识库访问权限。

#### 注册信息与校验

注册页面包含用户名、密码、确认密码三个输入项，均为必填。

用户名去除首尾空白后，长度为 3～32 个字符，仅支持英文字母、数字和下划线。用户名不区分英文字母大小写，且不得重复；登录时使用相同的识别规则。

密码长度为 8～64 个字符，区分大小写。密码与确认密码必须一致。

输入不符合要求或用户名已存在时，提示具体原因，不创建账号。页面与服务端均执行校验。

注册成功后跳转登录页面，由用户使用新账号登录。账号角色及初始知识库权限遵循既定规则。

**验收标准：**

- 用户注册成功后，其账号角色为普通员工。
- 修改注册请求中的角色参数，也不能创建管理员账号或获得管理员权限。
- 预置的管理员和员工账号均能正常登录；员工账号不能执行文档上传、更新和删除操作。
- 使用错误的账号或密码登录时，系统提示失败，不建立已登录状态。

- 合法信息能够注册成功，并使用新账号登录。
- 用户名仅有大小写差异时，不能重复注册。
- 用户名不合法、密码长度不符合要求或两次密码不一致时，不创建账号，并提示原因。
- 绕过页面直接提交请求，也不能跳过上述校验。

### 4.2 员工账号管理

管理员可以查看已注册的普通员工列表，查看账号名称及已授权知识库，并授予或撤销知识库访问权限。

员工通过自行注册创建账号。第一版不提供管理员手动创建员工、停用或删除账号、重置密码及变更角色的功能。

员工列表不展示密码。普通员工不得访问管理列表或执行授权操作。

**验收标准：**

- 新注册员工能够出现在管理员的员工列表中。
- 管理员可以查看和调整员工的知识库授权，调整结果遵循既定的访问控制规则。
- 普通员工不能通过页面或接口访问管理列表、执行授权操作。

### 4.3 知识库管理

企业管理员可以创建、查看、修改和删除知识库，并为普通员工授予或撤销知识库访问权限。普通员工只能访问获授权的知识库，不得创建、修改、删除知识库或调整授权。

#### 知识库创建与修改

管理员创建知识库时，必须填写名称，可以填写简介。名称去除首尾空白后须为 1～50 个字符，且在当前演示环境中不重复；简介最多 500 个字符。

创建成功后，知识库为空，默认未向任何普通员工授权。

管理员可以修改知识库名称和简介。修改不改变文档归属、已有授权关系及历史会话关联。

输入不符合要求时，提示具体原因，不保存本次创建或修改。

**验收标准：**

- 合法信息能够创建空知识库，新知识库没有默认员工授权。
- 名称为空、长度超限、重名或简介超限时，不保存本次操作，并提示原因。
- 修改知识库名称和简介后，原文档、员工授权及历史会话关联保持一致。

#### 非空知识库删除

仅企业管理员可以删除知识库。

删除包含文档的知识库时，系统展示确认弹窗，说明知识库名称、包含的文档数量，以及删除后不可恢复，并要求输入当前登录管理员的密码。

管理员确认且服务端完成权限与密码校验后，系统才开始执行删除。取消操作或校验失败时，不执行任何删除。

系统先删除该知识库中的全部文档，再删除知识库及其授权关系。文档删除遵循已定义的规则：停止文件访问、检索和新问答使用；正在运行的处理任务不得使已删除文档重新发布。

只有全部文档删除完成后，才能删除知识库并向管理员提示成功。

**验收标准：**

- 删除非空知识库时，展示知识库名称、文档数量、不可恢复提示及密码输入框。
- 取消操作或输入错误密码时，知识库、文档和授权关系保持原状。
- 普通员工无法通过页面或接口执行知识库删除。
- 校验通过后，系统先完成全部文档删除，再删除知识库及其授权关系。
- 全部删除完成后，原文件地址和引用不能返回文档内容，新问答不能使用这些文档。
- 尚未完成全部删除时，不得提示删除成功。

#### 删除执行与失败处理

知识库开始执行删除后，暂停员工对该知识库的访问，包括文档查看、下载、检索和知识问答。同时禁止向该知识库新增或更新文档。

如果部分文档删除失败，保留知识库记录及尚未删除的文档，向管理员显示“删除未完成”和失败原因，并提供“重试删除”入口。该知识库继续保持暂停使用状态。

重试时继续清理剩余内容，不恢复已删除的文档。只有全部文档清理完成后，才删除知识库及其授权关系，并提示删除成功。

**验收标准：**

- 删除执行期间，员工不能访问该知识库中的资料，管理员不能向其中新增或更新文档。
- 模拟部分文档删除失败时，系统保留知识库记录，显示“删除未完成”，不提示成功。
- 重试删除能够继续清理剩余内容，不恢复已删除文档。
- 剩余内容全部清理完成后，知识库及其授权关系被删除。

### 4.4 文档管理

企业管理员负责文档的上传、更新和删除，文档处理成功后由系统自动发布。普通员工可以查看、下载自己有权访问的文件，不得上传、更新或删除文档。

#### 文档查看与下载

第一版“查看文档”指通过来源引用查看文档提取的原文片段。用户下载原文件后，使用本地软件查看全文。

TXT、文字型 PDF、DOCX 和 Markdown 均采用上述方式。第一版不提供完整文档的浏览器在线预览。

查看片段和下载文件时，仍须校验当前访问权限，并遵循文档更新、删除及知识库暂停使用的规则。

**验收标准：**

- 对四种支持的文件格式，均可通过有效引用查看原文片段，并下载有权访问且当前可用的原文件。
- 引用片段和下载入口遵循既定权限及来源失效规则，不要求提供全文在线预览。

#### 支持的文件格式与内容提取

- TXT：支持 UTF-8 编码的 `.txt` 文件。
- PDF：支持含可提取文字的 `.pdf` 文件，暂不支持扫描版 PDF。
- Word：支持 `.docx` 文件，暂不支持旧版 `.doc` 文件。
- Markdown：支持 UTF-8 编码的 `.md` 和 `.markdown` 文件。

**内容提取范围：** 提取文档中的文字内容，包括正文、标题、列表及表格中的文字。暂不识别图片中的文字，不保证复杂排版和复杂公式的完整还原。

Markdown 中的外部链接和图片地址不触发自动下载或网页抓取。

不支持的文件格式在上传时明确提示。文件上传后，如果发现文件损坏、无法解析或未提取到有效文字，则进入“处理失败”状态，并向管理员展示原因。

**验收标准：**

- 符合约定格式且包含有效文字的样例文件，能够完成处理，进入“已发布”状态。
- 不支持的文件格式不能上传成功，页面提示支持的格式。
- 文件损坏或无法提取有效文字时，显示“处理失败”及原因。
- Markdown 中的外部链接不会导致系统自动导入链接指向的内容。

#### 上传限制

每次上传一个文件，并指定其所属知识库。单个文件大小不超过 10 MB，按 10,000,000 字节计算；不允许上传空文件。

不符合格式、大小或非空要求的文件，系统拒绝接收，并提示具体原因，不进入文档处理流程。

第一版不提供一次选择多个文件的批量上传功能。

**验收标准：**

- 管理员可以选择知识库，并上传符合要求的文件。
- 未指定知识库、文件为空、格式不支持或大小超限时，系统拒绝上传并提示原因。
- 页面和服务端均执行上传限制，直接调用接口也不能绕过校验。
- 文件上传成功后归属指定知识库，并进入“处理中”状态。

#### 重复文件处理

同一知识库内，未删除文档的文件名不得重复。比较时包含扩展名，不区分英文字母大小写。“处理中”“处理失败”“已发布”三种状态均参与重名检查。

新增上传遇到同名文档时，拒绝本次上传，并提示“该知识库已存在同名文档，请使用替换文件功能或修改文件名”。原文档保持不变。

不同知识库允许存在同名文件。文档删除完成后，允许重新上传同名文件。

替换文件时，允许与被替换文档同名；若与该知识库内其他文档重名，则拒绝替换，原文档保持不变。

第一版不检测“内容相同但文件名不同”的重复文件。

**验收标准：**

- 同库同名新增被拒绝，原文档不变。
- 仅大小写不同的文件名，也按重名处理。
- 不同库可以上传同名文件。
- 重名校验在服务端执行，不能通过直接调用接口绕过。

#### 文档处理状态

| 状态         | 含义                                       | 是否可被检索和用于问答         |
| ------------ | ------------------------------------------ | ------------------------------ |
| **处理中**   | 文件已上传，系统正在提取内容并准备检索数据 | 否                             |
| **处理失败** | 内容处理未能完成，需要管理员处理           | 否                             |
| **已发布**   | 内容处理成功，系统自动将文档设为可用       | 是，仅限有对应知识库权限的员工 |

其状态流转规则为：

新上传的文档进入“处理中”状态。处理成功后自动变为“已发布”；处理失败后变为“处理失败”。第一版不设置人工发布操作。

文档只有在处理完成、检索数据可用后，才能标记为“已发布”。

**验收标准：**

- 文档处理期间显示“处理中”，其内容不参与检索和问答。
- 处理成功后自动显示“已发布”，获授权员工能够检索并基于其内容提问。
- 处理失败后显示“处理失败”及原因，不将未处理成功的内容用于问答。
- 整个流程无需管理员手动点击发布。

#### 处理失败与重试

文档处理失败后，保留已上传的文件，并向管理员展示失败原因。

管理员可以点击“重试处理”，使该文档从“处理失败”重新进入“处理中”。重试针对原文档进行，不创建新的文档记录。

重试成功后，状态变为“已发布”；再次失败则回到“处理失败”，并展示本次失败原因。

文档处于“处理中”时，不允许重复发起处理任务。第一版不提供自动重试。

文档处理遵循第 5 章“文档处理超时”的规则。处理超时后转为“处理失败”，允许管理员手动重试。

**验收标准：**

- 处理失败后，原文件仍然保留，管理员能看到失败原因和重试入口。
- 点击重试后，同一条文档记录进入“处理中”，不新增重复记录。
- 重复点击或重复提交请求，不会为同一文档启动多个同时运行的处理任务。
- 重试的成功与失败结果，分别对应“已发布”和“处理失败”。
- 处理失败后，系统不会自行启动下一次重试。

#### 文档更新

仅管理员可以通过“替换文件”更新已有文档。新文件必须符合上传格式、大小及非空要求。

新文件上传失败或未通过上传校验时，原文档保持原状。

新文件接收并通过上传校验后，文档进入“处理中”。此后新发起的查看、下载、检索和问答请求，不得再取得或使用旧内容。

新内容处理成功后，文档自动变为“已发布”；处理失败后变为“处理失败”，管理员可以重试处理新文件，或再次替换文件。

更新不改变文档所属知识库及其访问权限。第一版不提供历史版本查看和回滚功能。

**验收标准：**

- 使用超限或不支持的文件替换文档时，系统拒绝替换，原文档保持原状。
- 替换成功进入“处理中”后，旧内容不再被新的访问及问答请求使用。
- 新内容处理成功后，文档恢复可用，检索和问答使用新内容。
- 新内容处理失败后，不自动恢复旧内容；点击重试时，重新处理本次上传的新文件。
- 更新前后，文档所属知识库及授权范围保持一致。

#### 文档删除

仅企业管理员可以删除文档。执行删除前，系统要求管理员确认。

删除成功后，该文档不再出现在可访问的文档列表中。新发起的查看、下载、检索及问答请求，不得再取得或使用其内容。

已有来源引用再次被打开时，应提示“文档已删除”，不得返回原文。

“处理中”“处理失败”和“已发布”状态的文档均可删除。删除正在处理的文档后，后台处理结果不得使该文档重新发布。

第一版不提供回收站和文档恢复功能。

**验收标准：**

- 普通员工不能通过页面或接口删除文档。
- 管理员取消确认时，文档保持原状。
- 删除成功后，直接访问原文件地址不能取得文件内容，新问答也不能使用该文档。
- 删除处理中的文档后，即使原处理任务随后结束，该文档也不会重新出现在可用列表中。

### 4.5 访问权限控制

系统同时根据用户角色和知识库授权限制操作。

企业管理员负责文档维护，并为普通员工授予或撤销知识库访问权限。普通员工只能访问获授权的知识库，查找、查看、下载其中可用的文档，并基于这些文档进行知识问答。

文档的访问权限由所属知识库决定，第一版不提供单篇文档的独立授权。

未获授权的资料不得出现在员工的文档列表、查询结果、问答内容和来源引用中，也不得被下载。权限限制同时在页面和服务端生效。

员工没有任何知识库访问权限时，页面显示“暂无可访问的知识库，请联系管理员”，不展示企业文档内容。

回答生成期间，员工对知识库的权限被撤销或知识库开始删除时，系统确认状态变化后停止继续输出相关内容，提示访问已中止。后续访问执行既定的会话隐藏与权限规则。

**验收标准：**

- 员工甲仅获授权访问知识库 A 时，可以查找、查看、下载 A 中可用的文档，并基于这些文档提问。
- 员工甲不能访问知识库 B 中的文档，即使直接使用文件地址或调用接口，也不能取得文件内容。
- 知识库 B 中的内容不得被用于生成员工甲的回答，也不得出现在其来源引用中。
- 新注册员工登录后，看到无可访问知识库的提示，不能访问任何企业文档。
- 管理员为该员工授权知识库 A 后，员工能够访问 A，仍然不能访问未获授权的知识库 B。
- 预置演示员工登录后，可以直接访问预先授权的知识库。
- 生成回答时执行撤权或知识库删除，系统确认状态变化后不再继续向该员工输出相关内容，后续读取会话及引用受到限制。

### 4.6 AI 问答和来源引用

#### 文档查询范围

第一版支持员工通过 Agent 查找自己有权访问的企业文档。独立于 Agent 的文档查找功能不纳入第一版。

#### 问答范围

每次问答限定在员工当前选定的一个知识库内，不进行跨知识库检索。

系统仅使用该知识库中已发布、且当前员工有权访问的文档。处理中、处理失败或已删除的文档，不得参与新问答。

服务端校验员工对所选知识库的访问权限，不允许通过修改请求参数访问未获授权的知识库。

**验收标准：**

- 员工无需选中具体文档，即可针对所选知识库提问。
- 员工同时有知识库 A、B 的权限，但选择 A 提问时，回答依据和引用仅来自 A。
- 处理中、处理失败及已删除的文档不参与新问答。
- 员工修改请求中的知识库标识，也不能使用未获授权知识库中的内容。

#### 回答依据与资料不足处理

系统可以整理和概括文档内容，但回答中的企业规定、事实和操作要求必须有当前知识库内可用文档的支持。

文档足以回答问题时，系统根据文档作答，并提供支撑相关结论的来源引用。

文档只能支持部分回答时，系统回答有依据的部分，并明确说明哪些问题缺少依据。

没有足够依据时，系统提示“当前知识库可用资料中未找到足够依据，无法确认”，不编造答案或来源引用，不以模型的一般知识补充缺失的企业规定。

未检索到相关内容，不得直接解释为企业不存在相应规定。

**验收标准：**

- 对有明确文档依据的问题，回答与文档一致，并提供对应引用。
- 对包含多个子问题、但资料只覆盖其中一部分的问题，只回答有依据的部分，其余部分明确说明无法确认。
- 对资料未覆盖的问题，不编造具体规定、数值或引用。
- 用户要求“猜一个答案”时，系统仍遵守上述依据限制。

#### 来源引用展示

回答中有文档依据的结论，应关联对应的引用编号，例如〔1〕、〔2〕，方便用户判断依据与结论的对应关系。

点击引用后，展示来源文件名、支撑该结论的原文片段，并提供下载原文件的入口。

PDF 引用展示原文件页码，按文件实际页序从第 1 页开始计数。Word、TXT 和 Markdown 通过文件名及原文片段定位，第一版不要求页码。

原文片段来自文档提取内容，不得由模型改写或编造。文件名、页码等来源信息应来自文档处理结果。

查看引用及下载原文件时，系统仍需校验用户当前的访问权限；文档已删除时，提示“文档已删除”，不返回原文。

**验收标准：**

- 点击回答中的引用编号，能够看到对应文件名和原文片段。
- 原文片段能够在对应文档中核对，并支撑所关联的回答结论。
- PDF 页码能定位到包含引用内容的页面。
- Word、TXT 和 Markdown 不展示未经确认的页码。
- 有权限且文件可用时，能够下载原文件；无权限或文件已删除时，不能通过引用入口取得文件内容。

#### 资料冲突处理

本次问答检索到的文档，对同一适用条件下的问题给出相互矛盾的规定，且无法根据文档内容确认应采用哪项规定时，系统展示不同说法及各自的来源引用，并提示用户联系管理员核实，不自行选择其中一种作为确定答案。

不得仅根据文件上传时间决定哪项规定有效。

第一版仅处理本次问答发现的冲突，不提供全知识库自动冲突扫描功能。

**验收标准：**

- 准备两份对同一条件分别规定“10 个工作日”和“15 个工作日”的文档，提问时应展示两种说法及对应引用，不输出唯一确定期限。
- 调换两份文档的上传先后顺序，不应仅因此改变对规定有效性的判断。
- 对适用条件不同、实际并不矛盾的规定，回答应说明各自适用范围。

#### 多轮对话

同一对话关联一个知识库。员工可以连续提问，系统结合此前对话理解省略、指代和追问，例如“那需要什么材料”。

每轮回答仍须依据当前选定知识库中、员工有权访问的已发布文档。历史对话用于理解问题，不得代替文档作为事实依据。

切换知识库时开启新对话，不携带原知识库的对话上下文。

如果无法根据上下文确定用户的意思，系统应请求用户澄清，不自行猜测关键条件。

**验收标准：**

- 连续询问“报销需要哪些材料”和“那最晚什么时候提交”，系统能够理解第二问仍然针对报销。
- 对话涉及多个事项、指代无法确定时，系统请求澄清。
- 切换知识库后，新对话不使用原知识库的聊天内容。
- 对话过程中，来源文档被替换、删除或失去访问权限后，后续回答不得继续将旧内容作为依据。

#### 输入与上下文范围

单条问题最多 2,000 个字符，去除首尾空白后不得为空。不符合要求时，提示原因，保留输入内容，不发起模型请求。

每次生成回答时，除当前问题外，最多使用最近 10 轮正常完成的问答理解上下文。更早记录仍然保存，但不参与本轮理解。页面提示“较早的对话未纳入本次上下文，如有需要请补充背景”。

历史对话仅用于理解问题；文档依据仍按每轮当前权限及有效状态重新检索。

如果请求仍超过所选模型的容量，明确提示用户缩短内容或新建对话，不将其显示为资料不足。

#### 会话历史

系统按账号保存会话，记录关联知识库、用户提问、系统回答及对应引用信息，并按对话顺序展示。

用户可以通过历史会话列表查找自己的会话。刷新页面或退出后重新登录，已成功保存的对话仍然保留。

用户可以在原会话中继续提问，问答范围仍限定为该会话关联的知识库，并重新校验当前访问权限。

普通员工只能访问自己的会话，不得通过修改请求参数取得其他员工的会话内容。

**会话基本操作：**

用户选择有权访问的知识库后，可以新建对话。同一知识库可以创建多个独立会话，各会话的对话上下文相互隔离。

历史会话按最后一条消息的时间倒序排列。标题默认取首条问题的前 20 个字符，超出部分显示省略号；首条问题被编辑后，标题同步更新。第一版不提供手动改名。

用户可以打开自己的历史会话，查看并继续提问；访问仍遵循当前知识库权限规则。

用户可以删除自己的会话，删除前需要确认。删除会话同时删除其消息及引用记录，不删除知识库中的文档，不提供恢复功能。

删除正在生成回答的会话时，同时停止该会话的生成；旧任务后续返回的结果不得重新创建已删除的会话。

即使用户已失去关联知识库的访问权限，仍可删除自己的会话，但不能因此查看隐藏的内容。

**验收标准：**

- 完成多轮问答后刷新页面，已保存的消息顺序和引用关系保持一致。
- 退出并重新登录后，能够找到自己的历史会话。
- 打开原会话继续提问时，仍使用原关联知识库。
- 员工甲不能通过会话地址或接口读取员工乙的对话。
- 继续提问时，仍执行当前知识库权限、文档可用状态及回答依据限制。

- 同一知识库下的两个会话，不混用对话上下文。
- 历史列表按规则生成标题并排序；无权限会话继续使用既定的隐藏提示。
- 删除会话后，其消息不可访问，知识库文档保持不变。
- 用户不能删除其他人的会话；已删除会话不会被后台任务重新创建。

#### 访问权限变化

员工对知识库的访问权限被撤销后，系统保留相关会话记录，但不再向该员工展示会话正文、来源片段及下载入口，也不允许继续提问。

历史会话列表仅显示“关联知识库不可访问”，不展示原会话标题或消息摘要。

员工重新获得该知识库的访问权限后，可以恢复访问原会话。

服务端在读取历史会话、查看引用、下载文件及继续提问时，均须检查当前权限，不能仅依据会话创建时的权限放行。

会话关联的知识库已被删除时，保留会话记录，但不展示原标题、摘要、正文、来源片段和下载入口。历史列表显示“关联知识库已删除”，不允许继续提问。用户仍可以删除自己的会话。

**验收标准：**

- 员工完成问答后，管理员撤销其知识库权限。员工再次请求历史正文、引用、下载或继续提问时，均被拒绝。
- 权限撤销后，历史列表不再展示该会话的原始标题或摘要。
- 重新授权后，原会话恢复可访问，消息顺序不变。
- 直接调用接口，也不能绕过权限检查。
- 删除知识库后，关联历史会话显示“关联知识库已删除”；直接调用接口不能取得隐藏内容；用户仍能删除自己的会话。

#### 来源变更后的历史引用

历史回答保留为当时的对话记录。其引用的文档被替换或删除后，回答展示“来源已变更或不可用，此回答可能已过期”的提示。

替换文件接收并通过上传校验后，旧引用即失效。若替换文件上传失败或未通过上传校验，原文档及原引用保持不变。

点击失效引用时，说明来源已更新或已删除，不展示旧原文片段，不提供旧文件下载，也不将引用直接指向新版本内容。

同一回答包含多个引用时，分别判断引用是否有效；仍然有效的引用可以正常访问。

继续提问时，系统使用当前可访问的有效资料重新检索，不将历史回答作为事实依据。

上述历史内容仍受知识库权限控制，失去权限后不再展示。

**验收标准：**

- 替换或删除被引用文档后，相关历史回答出现过期风险提示。
- 点击失效引用，不返回旧原文或旧文件，也不会直接打开新版本冒充原依据。
- 同一回答中未受影响的引用，仍可正常访问。
- 替换文件上传失败或校验不通过时，原引用不因此失效。

#### 回答生成与展示

用户提交问题后，页面显示等待反馈；开始收到回答内容后，逐步展示正文，并显示“正在生成”。

回答正常生成结束后，标记为已完成，并提供与回答对应的来源引用。

生成过程中发生异常中断时，明确提示“回答未完成”，不得将已显示的部分内容当作完整回答。

模型服务异常、连接中断等系统故障，不得显示为“当前知识库未找到足够依据”。

生成期间的权限与知识库状态变化，遵循“4.5 访问权限控制”中的中止规则。

**验收标准：**

- 提交问题后，页面提供等待反馈，不出现长时间无反馈的空白。
- 收到回答内容后逐步展示，无需等待全文生成完毕。
- 正常结束后，回答显示完成，并具备对应的引用信息。
- 模拟生成中途断开连接时，已显示的半段回答被标记为未完成。
- 服务故障不会被错误展示为资料不足。

#### 回答中断与重试

因系统异常或超时导致回答未完成时，保留已经显示的内容，标记“回答未完成”，并在会话历史中保留该状态。

仅对会话最后一轮的未完成回答提供“重新生成”入口。用户已发送后续问题时，较早的未完成回答保留原状态，不再允许重试。

服务端同样校验该回答是否属于会话最后一轮且处于未完成状态；不符合条件时拒绝重试，不修改已有消息。

用户点击重新生成后，系统针对原问题，结合此前正常完成的对话上下文及当前有效资料，重新生成回答。重新生成前须校验当前知识库访问权限。

新回答替换本次未完成回答，引用信息同步更新；不与旧片段拼接，不重复创建用户问题。未完成的回答不作为后续对话上下文。

再次失败时，仍明确显示失败或未完成状态。第一版不自动重试。

**验收标准：**

- 中断后刷新页面或重新登录，仍能识别该回答未完成。
- 点击重新生成，不新增重复的用户问题，新回答不与旧片段拼接。
- 重新生成成功后，正文与引用相互对应。
- 权限已被撤销时，不能重新生成。
- 中断后，系统不会未经用户操作自动发起下一次生成。
- 会话最后一轮的未完成回答可以重新生成；发送后续问题后，较早的未完成回答不再显示重试入口。
- 直接调用接口重试较早的未完成回答时，系统拒绝操作，已有后续消息保持不变。

#### 停止生成

回答生成期间，用户可以编辑输入内容，并通过“停止生成”按钮中止当前回答。

停止后，保留已生成的部分内容，标记“已停止”，恢复发送操作。该未完成回答不作为后续问答的事实依据或对话上下文。

停止操作生效后，不再向该回答追加内容。原生成任务后续返回的结果，不得覆盖重新发送后生成的新回答。

**验收标准：**

- 主动停止后，部分回答保留并显示“已停止”，不再追加内容。
- 即使旧任务稍后返回结果，也不能覆盖新回答。

#### 编辑问题并重新发送

同一会话同时只生成一个回答。生成期间允许编辑输入内容，停止当前生成后可以重新发送。

用户停止当前回答后，可以编辑最近一条已发送的问题。重新发送时，替换该条问题并重新生成对应回答，不重复创建用户问题，不拼接旧回答片段，引用信息随新回答更新。

新回答使用编辑后的问题、此前正常完成的对话上下文及当前有效资料，重新执行权限检查和检索。

第一版不支持编辑更早的历史问题，不保留同一问题的多个回答版本或对话分支。

**验收标准：**

- 编辑最近一条问题并重新发送后，原问题及对应回答被替换，不新增重复问题。
- 新回答根据修改后的问题重新检索，不沿用被停止的回答作为依据。
- 第一版不提供更早消息的编辑入口或对话分支功能。

## 5. 非功能需求

### 部署与演示环境

第一版支持在开发者电脑上本地运行，通过预置账号和演示资料完成核心功能演示，不要求提供公网访问地址。

核心演示流程包括：管理员维护知识库、授权员工、上传并处理文档，以及员工登录、提问、查看引用和下载文件。

在线部署及面向外部访客的使用要求，留待后续版本定义。

### 模型服务依赖

第一版应用在开发者电脑上运行，通过外部模型 API 生成回答，支持流式输出，需要网络连接及有效的模型服务凭证。

模型服务连接失败、调用失败或响应中断时，向用户展示明确的异常反馈，并遵循已定义的回答中断与手动重试规则，不得将服务异常解释为资料不足。

模型服务凭证由后端配置管理，不向浏览器暴露，也不提交到代码仓库。

### 演示负载

性能测试以同一时间一个正在生成的问答请求为基线。允许同时打开管理员和员工页面，验证权限和资料变更流程。第一版不承诺多人同时问答的性能指标。

单请求性能测试基线不代表系统只允许一个账号使用。

### 问答响应与超时

提交问题后，页面在 1 秒内展示等待反馈。

从提交起，超过 30 秒仍未收到回答正文，则结束请求并提示超时。单次请求总时长不超过 120 秒。

超时时尚无正文，则显示失败提示；已有部分正文，则保留内容并标记“回答未完成”，提供手动重新生成入口。

请求结束后恢复发送操作，原请求后续返回的内容不得继续追加或覆盖新回答。

### 文档处理超时

单次文档处理时长上限初始为 300 秒，可通过后端配置调整。文件接收并通过上传校验、进入“处理中”时开始计时，覆盖排队、内容提取和检索数据准备，直至处理完成。

到达上限仍未完成时，结束本次处理任务，将文档标记为“处理失败”，展示“文档处理超时，请重试”，释放该文档的处理任务占用，并保留已上传文件供管理员手动重试。

每次手动重试进入“处理中”时重新计时。原超时任务随后返回的结果，不得使文档重新发布，也不得覆盖重试任务的状态或结果。

300 秒是第一版初始超时配置，不代表实际处理耗时；实际耗时在验收时记录。如调整配置，验收报告须记录所用值。

**验收标准：**

- 模拟处理达到 300 秒仍未完成时，文档进入“处理失败”，显示超时原因，管理员能够手动重试。
- 手动重试重新计算处理时长，不继承上一次任务已用时间。
- 原超时任务后续返回时，不能重新发布文档或覆盖重试结果。

### 数据持久化与重启恢复

正常关闭并重新启动应用后，已保存的账号、知识库、授权关系、文档及会话记录保持不变。

因应用关闭而中断的文档处理任务，重启后标记为“处理失败”，说明中断原因，允许管理员手动重试。

因应用关闭而中断的回答，重启后标记为“回答未完成”，保留已保存的部分内容，允许手动重新生成。

已完成的文档和回答不受重启影响。第一版不自动恢复中断任务。

知识库删除未完成且应用关闭时，重启后保留已完成的删除结果和剩余清理范围，显示“删除未完成”。知识库继续暂停使用，由管理员手动重试剩余内容，不恢复已删除文档，不自动恢复删除任务。

**验收标准：**

- 模拟知识库删除中断，重启后仍不可访问该库，管理员能够重试并完成剩余删除，已删除文档不会恢复。

## 6. 验收方案

### 验收数据集

使用两个知识库、合计 12 份演示文档，覆盖 TXT、文字型 PDF、DOCX 和 Markdown。

准备 20 组固定问答案例：资料足以回答 8 组、部分有依据 4 组、无依据 4 组、资料冲突 2 组、连续追问 2 组。

每组预先记录问题、预期回答要点和预期来源。多轮案例记录完整提问顺序。

### 问答质量判定

人工检查回答的正确性、完整性、引用有效性和场景行为。无需逐字匹配预期文本，但必要要点和业务含义必须符合预期。

多轮案例的必要轮次均须通过。超时、调用失败或回答中断不能计为通过。

第一版要求 20 组全部通过。验收时记录模型、实际回答、引用和失败原因。其他功能按各自验收标准检查。

### 性能验收

在已约定的本地环境和单请求负载下，依次执行 20 组固定问答案例，多轮案例按每次请求分别记录。

每次记录：页面等待反馈耗时、首段回答正文出现耗时、回答完成耗时，以及成功、失败或超时结果。

等待提示和“正在生成”状态不算回答正文。耗时从用户提交问题开始计算，包含检索、网络及模型调用时间。

检查页面是否在 1 秒内反馈，以及 30 秒无正文、120 秒总时长的超时规则是否生效。

验收报告记录测试时间、电脑配置、模型服务及模型名称、资料规模。成功请求汇总耗时，失败和超时请求单独列出，不得计为成功。

## 7. 第一版暂不实现

- 多Agent协作
- 自动修改企业业务数据
- 复杂工作流
- 大规模分布式部署
- 面向用户的独立文档查找功能。
- 完整文档的浏览器在线预览。
- 企业邀请及加入审批流程。
- 通过网页链接自动获取和导入文档内容。
- 公网部署及在线访客体验。
- 本地模型部署，以及外部模型 API 与本地模型之间的切换。

## 8. 后续版本方向

第一版完成后，尝试本地模型部署，并支持在外部模型 API 与本地模型服务之间切换。具体模型、运行环境及切换方式，在后续版本设计时确定。
